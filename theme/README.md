# テーマ体系づくりの引き継ぎ書

ほかのセッションで、法律科目のテーマ体系の素案を作り続けるための引き継ぎ書です。
新しいセッションは、**作業を始める前にこのファイルを最後まで読んでください。**
そのうえで、できあがっている `kenpo.yaml`・`keiho.yaml`・`keiso.yaml` とそれぞれのメモを見本として読んでください。

---

## 1. 何のための体系か

D-D Works（ユーザーが自分で作っている作業ツール群）の中に、資格試験の過去問から○×問題を作って出題するアプリを作る。

- 過去問の原文から「問題オブジェクト」を切り出す。選択肢の記述（ア・イ・ウ…）は1つずつに分ける。
- 問題オブジェクトには、出典・原文・答え・解説のほか、**テーマのタグ**を付ける。
- 20問・50問の疑似テストを解いて正解・不正解を集め、どのテーマが分かっていないかを見る。
- 間違えた問題からは、同じテーマのタグを持つノートを開いて学び直す。ノートにも同じタグを付ける。

つまりテーマ体系は、**出題アプリとノートが共通で使うタグの辞書**。タグの言い方がばらばらだと集計が割れて弱点が見えなくなるので、体系を先に用意する。

同時にテーマ体系は、**法学の論点を見渡す「概要地図」**でもある。科目ごとに、どんな分野があり、どこにどんな論点があるかを一目で見渡せることを大事にする。タグの辞書としての使いやすさと、地図としての見渡しやすさの両方を満たすように作る。

最初の対象は、司法試験予備試験の短答の法律科目（憲法・行政法・民法・商法・民事訴訟法・刑法・刑事訴訟法）。会計もいずれ同じ規則で作る（会計は法学より階層的で、構造エリアが深めになる見込み）。

## 2. 進め方の方針

- **粗い骨組み（構造エリア）を先に作る。** 論点は網羅しなくてよい。構造の形が分かる程度の代表例だけ入れる。
- 細かい論点は、あとで問題にタグを付けながら AI が足し、ときどき似たものをまとめて育てる。
- 素案なので完璧を目指さない。人が直す前提で、迷ったことはメモに残す。
- **地図は「ざっくり作り、間違っている前提で使う」**（2026-10-22 決定）。どの説が判例・通説か、論点の置き場所が正しいかなどは、最初から詰めない。ユーザーがその単元を学ぶときに、AI がその単元を深掘りして（基本書・判例・教材で確かめて）、地図を直しながら理解していく。

## 3. 規則

### 3-0. 地図の層（段階）

- 地図は、基本は**2層**：構造エリア → 論点エリア。
- 必要なら**3層まで**にしてよい：「構造1・構造2・論点」または「構造・論点1・論点2」。
- 層を増やしすぎると、地図全体を見渡す役割が弱くなる。**4層以上がほしくなったら、1枚に詰め込まず「概要地図」と「詳細地図」に分ける。** 詳細地図は何層でもよい。
- ここでいう「層」は地図の大きな区分（エリア）のこと。各エリアの中の深さ（「段」）とは別。段の決まりは 3-1 のとおり（構造エリアは何段でもよい、論点エリアは最大3段）。
- 今の素案（憲法・刑法・刑訴）はすべて2層。

### 3-1. 構造エリアと論点エリア

|  | 構造エリア（structure） | 論点エリア（issue） |
|---|---|---|
| 中身 | 科目・分野・小分野のような分類の枠、または手続の段階 | 実際に問われる論点 |
| 形 | ポリヒエラルキー（親を複数持てる）か、流れ図（`next`、3-4）。分野ごとにどちらを使ってもよい | 樹形図＝モノヒエラルキー（親は1つだけ） |
| 段数 | 何段でもよい | **最大3段** |

- 構造エリアの形が2つあるのは、ヒエラルキー（階層）は分類（何が何の一種か）には向くが、手続（何の次に何をするか）には向かないから。流れに向く分野は流れ図で表し、その各段階に論点の樹形図をぶら下げる。1科目の中で両方を使ってもよい（例：刑訴は、手続の段階を流れ図、基本原則・証拠などをヒエラルキーにしている）。
- 論点の**第1段**は、構造エリアの項目を親にする。親は複数でもよい（ここが構造と論点のつなぎ目）。ぶら下げる先は構造の最下段でなくてもよい。
- 論点の**第2段・第3段**は、すぐ上の論点を親に1つだけ持つ。構造エリアには直接つながない。
- 論点エリアの中では複数の親を持たせない。置き場所に迷う論点は、第1段の論点ごと複数の構造にぶら下げて解決する。
- 4段目が要りそうなときは、第1段を分けるか、構造エリアの側を1段深くする。
- **学説（〇〇説）**は、論点の子として1段使って立ててよい（例：公共の福祉 > 一元的内在制約説）。ただし：
  - 学説は**ひとまとまりのグループ**として見えるようにし、ほかの子の論点と混ざらないようにする（説だけを独立して見られるようにするため）。
  - 学説の段は、**論点の「最大3段」のカウントに入れない**。第3段の論点の下に学説を置いてもよい。
  - 判例の判断の枠組み（例：危険の現実化）を学説のグループに入れるかは、そのつどメモに書く。
- 構造エリアは、迷うものを複数の親にぶら下げてよい（例：法の下の平等は人権総論と人権各論の両方）。ただし科目のような最上位はヒエラルキーらしく保ち、全部をフラットな網にはしない。数は少なめにし、基本書の目次や試験の出題範囲の一般的な分け方を手がかりにする。

### 3-1-2. 科目をまたぐテーマ（所属と目印）

- 令状主義（憲法・刑訴）、地方自治・損失補償（憲法・行政法）のように、複数の科目にまたがるテーマがある。
- そのテーマは、**作っているときの科目の樹形図に属する**（所属は1つ）。例：憲法を作るときに立てた令状主義は、憲法の樹形図に属する。
- ほかの科目からも参照されていることは、**矢印のような目印**で示す。例：憲法の令状主義に「刑訴からも参照」の目印を付け、刑訴の樹形図でも同じテーマを目印付きで見せる。
- つまり、表示は両方の科目の樹形図に出る。所属は作った科目で、ほかの科目の樹形図では「よその科目から来ている」ことが目印で分かるようにする。

### 3-2. エイリアス（言い換え）

- **純粋な言い換えだけ。** 表記ゆれ・略称・語順の違いなど、指しているものがまったく同じもの。
  - よい例：「人権の享有主体性」「人権享有主体性」「人権の享有主体」
- **学説上の同一視はエイリアスにしない。** 混ぜると、学説の対立や考え方の移り変わりが辞書から消える。
  - 悪い例：「公共の福祉」のエイリアスに「人権相互の矛盾・衝突を調整する原理」を入れる（一元的内在制約説という一つの立場）。
  - こういうものは別のテーマとして立てて「関連」でつなぐ。
- 法改正で変わった古い呼び名（例：懲役・禁錮 → 拘禁刑）も、中身が違えばエイリアスにしない。
- 判断に迷うものは、エイリアスに入れたうえで memo に「人の確認が必要」と書く。

### 3-2-2. 法改正で変わった制度（古い制度の目印）

- 法改正で制度が変わったとき（例：懲役・禁錮 → 拘禁刑、2023年の性犯罪の改正）は、古い制度のテーマも別に立て、**古い制度のほうに目印**を付ける。新しい制度のほうには目印を付けない。
- 改正前の過去問には、古い制度のテーマのタグを付ける。

### 3-3. 関連（related）

- 上下関係ではないが関わりの深いテーマどうしをつなぐ。例：「営業の自由」と「規制目的二分論」。
- 向きを持たない。構造・論点のどちらにも張ってよい。科目をまたいでもよい。
- **片側にだけ書く。** 新しい科目からほかの科目のテーマへつなぐときは、新しい科目の側に書く（既存の YAML を書き換えずに済む）。

### 3-4. 流れ図（next：次の段階）

- 構造エリアは、ヒエラルキーの代わりに**流れ図**で表してよい。流れ図は構造エリアの正式な形の一つで、補助の図ではない。流れ図は、構造エリアに **`next`（次の段階）** を書いて表す。刑訴で試し、うまくいった。
- 手続法に限る決まりはない。ただ、流れ図が合うのはふつう手続法（刑事訴訟法・民事訴訟法、行政法の行政手続や行政救済の一部）になるはず。これは制約ではなく、そうなるはずという見込み。
- 小さすぎる流れ図は作らない。流れが短く、分類で表せる部分はヒエラルキーにして、2つの形の使い分けをはっきりさせておく。
- `next` は手続の上で次に進む段階の ID。向きを持つ。分かれ道は複数書く。差戻しのように前へ戻る矢印もよい。
- **構造エリアどうしだけ**に張る。論点には張らない。
- タグ付けと集計は今までどおり親子関係で行う。`next` は流れ図を描くためだけのもの。
- 流れに乗らない枠（基本原則・訴訟主体・証拠など）には `next` を書かない。
- 作ってみた結果、論点は手続法でも全部樹形図に収まった。論点に流れの形は要らない。手続の時間の流れ（勾留の期間など）は、論点1つのタグにして、流れ図はノートの側に描く。
- アプリの画面では、`next` がある科目は左側（構造）を流れ図、右側（論点）を樹形図で見せる想定。

### 3-4-2. この形で表しきれないとき（注意を出す）

- 地図の形は「構造エリア（ポリヒエラルキーか流れ図）＋論点エリア（樹形図）、つなぎ目はポリヒエラルキー」。これで表しきれないものが出たら、無理に押し込まない。
- そのときは、**ユーザーへの返事の中で「注意」として目立つように知らせる。** あわせてメモの「人が決めるべきだと思う点」にも残す。
- 例：4層以上が要りそう／論点の第2・3段に親が複数要りそう／論点の側に流れの形が要りそう／ヒエラルキーにも流れ図にも収まらない分野がある。

### 3-4-3. 地図に載せないもの（表・模式図）

- 構造を表す形は、**ポリヒエラルキー（樹形図）と流れ図の2つだけ**にする（2026-10-21 決定）。
- **比べる表**（例：逮捕3種類の比較、仮差押えと仮処分）や、**模式図**（当事者の関係図、会社の機関などの組織図）は、地図（構造エリア・論点エリア）には載せない。
- これらは、地図からリンクして開く**論点のドキュメント（ノート）の中に、表や図として入れる**。地図の側では、比べる相手どうしを関連でつなぐだけにする。
- 手続の時間の流れ（勾留の期間など）をノートの側に描くのも同じ考え方（3-4）。

### 3-5. 名前の付け方

- 名前（正式な見出し）は、基本書や試験でいちばん普通に使われる言い方にする。
- 学説の立場を含まない、中立な言い方にする。
- 1つのテーマには1つの意味だけを持たせる。**同じ言葉が科目によって違う意味になるときは、名前に科目名を添えて別のテーマにする。**
  - 例：「錯誤（刑法）」「故意（刑法）」「因果関係（刑法）」「裁判（刑事訴訟法）」「自白（刑事訴訟法）」
  - 学説名が科目内でぶつかるときも同じ：「間接適用説（私人間効力）」「二元説（選挙権）」
  - **ぶつかる言葉には、全部の科目で科目名を添える。** 主に使う科目でも省かない（例：「正当防衛（刑法）」と「正当防衛（民法）」）。
  - 民訴と刑訴で重なる原則も同じで、1つにまとめず科目ごとに分けて添える（例：「自由心証主義（刑事訴訟法）」「自由心証主義（民事訴訟法）」）。
  - まだ作っていない科目とぶつかると分かっている言葉にも、先に添えておく。
- 判例名はテーマにしない。判例は問題オブジェクトの別の項目として持つ。
- 名前とエイリアスは、全科目を通して重ならないようにする（チェックスクリプトで確かめる）。

### 3-6. ID の付け方

- 英小文字・数字・ハイフンだけ。名前を変えても ID は変えない。
- 構造エリアは科目の接頭辞を付ける：`kenpo-`（憲法）・`keiho-`（刑法）・`keiso-`（刑事訴訟法）。ほかの科目は、`gyosei-`（行政法）・`minpo-`（民法）・`shoho-`（商法）・`kaisha-`（会社法）・`minso-`（民事訴訟法）を使う。
- 論点は接頭辞なしのローマ字（例：`jinken-kyouyuu-shutaisei`）。ぶつかるときだけ科目名を足す（例：`toujisha-shugi-keiso`）。
- 複数の科目で共有しそうな構造は接頭辞を付けない（例：`chihou-jichi`。行政法でも親にする予定）。

## 4. ファイルの形式

YAML。人が読んで直しやすいことを優先する。

```yaml
- id: kenpo-jinken            # 変わらない ID
  name: 人権                  # 正式な見出し
  kind: structure             # structure（構造エリア）・issue（論点エリア）・theory（学説）
  parents: [kenpo]            # 親の ID。構造と論点の第1段は複数可、論点の第2・3段と学説は1つだけ。最上位は空
  aliases: [基本的人権]        # 純粋な言い換えだけ
  related: []                 # 関連（向きなし、片側にだけ書く）
  next: []                    # 次の段階（流れ図にする構造エリアだけ）
  old_law: 2025               # 法改正で変わった古い制度のテーマだけ。改正の年
  articles: [憲法13条]         # 関係する条文番号。複数可、ほかの法令もまぜてよい
  memo: ""                    # 分け方に迷った理由など
```

- 空の項目（aliases・related・next・old_law・articles・memo）は省いてよい。最初の1件（科目の最上位）だけ全項目を書いている（old_law・articles は除く）。
- **学説**は `kind: theory`。親は論点1つだけ。学説の下に子は置かない。段には数えない。ページでは子の論点の後ろに「学説」のまとまりとして出る。
- **科目をまたぐ参照**は、参照する側の科目のファイルに `ref` の行を書く。参照先の科目のファイルは書き換えない。
  ```yaml
  - ref: reijou-shugi         # ほかの科目に属するテーマの ID
    parents: [keiso-sousa]    # この科目での置き場所（このファイルの構造エリア）
    memo: ""                  # この科目に出す理由など
  ```
  ページでは、参照する側の樹形図に「↙ 憲法から」、属する側の樹形図に「↗ 刑事訴訟法からも参照」の目印が出る。ref の行はテーマの数に入れない。学説は参照にしない。
- **古い制度**は `old_law` を付けて別のテーマとして立て、新しい制度のテーマと `related` でつなぐ（例：懲役・禁錮 → 拘禁刑）。ページでは「旧制度」の目印が出る。
- **条文番号**は `articles` に「法令名＋条番号」で書く（2026-10-21 決定。今は入口だけ作り、例を少し入れた段階）。
  - 書き方：`民法709条`・`刑法230条の2`・`刑事訴訟法198条2項`・`刑事訴訟法337条1号`・`民法398条の2第1項`。数字は算用数字、法令名は正式名称（略さない）。
  - 1つのテーマに複数書いてよく、ほかの法令の条文もまぜてよい（例：名誉毀損罪における真実性の証明 → `[刑法230条の2, 憲法21条1項]`）。
  - 主に論点に付ける。構造に付けてもよい（例：正当防衛（刑法）→ 刑法36条1項）。学説には付けない（親の論点に付ける）。
  - ページでは詳細欄に「条文」として出て、絞り込みの欄で条文番号でも探せる。
- ファイルの先頭にコメントで規則の要約を書き、構造エリア → 論点エリア → 参照（ref）の順に、見出しコメントで区切って並べる（既存の3ファイルと同じ）。

## 5. 1科目を作る手順

1. **構造エリアを決める。** 基本書の目次の並びと、予備試験の短答の出題範囲を手がかりにする。必要なら Web で基本書の目次を調べる。
2. **流れが合う分野なら**（ふつうは手続法）、構造エリアを流れ図にする。段階に `next` を張り、流れに乗らない枠はヒエラルキーで分ける。層は基本2層、多くて3層（3-0）。
3. **論点を代表例だけ入れる。** 構造の形が分かる程度（目安：1科目で論点60〜100件）。学説は論点の子として立て、学説のグループにまとめる（3-1。段のカウントに入れない）。
4. **ほかの科目とのつながり**を `related` で張る。科目をまたぐテーマは 3-1-2 のとおり、作った科目に属させ、ほかの科目からは目印付きで参照する。
5. **規則チェック**を通す（6章）。全科目まとめて通すこと。
6. **メモを書く**（`<科目>_memo.md`）。既存のメモと同じ見出しで：
   - 全体の作り方
   - 分け方に迷ったところと、どう決めたか（表）
   - 複数の親にしたもの、その理由（構造・論点に分けて全件）
   - エイリアスにしたもの・しなかったもの・人の確認が必要なもの
   - 人が決めるべきだと思う点
7. **樹形図ページを作って公開する**（6章）。ほかの科目のページも、新しい科目との関連が見えるように作り直して更新する。
8. **コミットしてプッシュする。** YAML とメモはユーザーにファイルとしても送る。

## 6. 道具

すべてリポジトリの直下（`/home/user/Discussion` など）から実行する。

```sh
# 規則チェック（全科目まとめて。エラーがなければ件数だけ出る）
python3 theme/check_theme.py theme/kenpo.yaml theme/keiho.yaml theme/keiso.yaml theme/<新しい科目>.yaml

# 樹形図ページを作る（--ref にはほかの全科目を渡す。関連の名前を出すため）
python3 theme/build_tree.py theme/keiso.yaml theme/keiso_tree.html --ref theme/kenpo.yaml theme/keiho.yaml
```

- `check_theme.py`：ID の形と重複、親・関連・次の段階の参照先、論点の段数（3段まで。学説は数えない）、第2・3段の親が1つか、学説の親が論点1つか・学説の下に子がないか、`ref` の行の参照先と置き場所、`old_law` の形、`articles` の形と重複、循環、名前とエイリアスの重複を確かめる。1科目だけを渡すと、ほかの科目への関連が「存在しない」と出るので、必ず全科目を渡す。
